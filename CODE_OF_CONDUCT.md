# 🤝 Code of Conduct

## Our Pledge

We as members, contributors, and maintainers of **Flow Task Manager** pledge to make participation in this project a respectful, inclusive, harassment-free, and professional experience for everyone.

We are committed to creating an open and welcoming environment where developers can collaborate, learn, contribute, and exchange ideas constructively.

---

## 🌟 Our Standards

Examples of behavior that contributes to a positive project environment include:

- Demonstrating empathy and respect toward other contributors
- Respecting differing opinions, experiences, and viewpoints
- Providing constructive and actionable feedback
- Accepting constructive feedback professionally
- Taking responsibility for mistakes and learning from them
- Focusing discussions on what benefits the project and its community
- Communicating clearly and professionally
- Supporting new and less-experienced contributors
- Collaborating in good faith

Examples of unacceptable behavior include:

- Harassment, intimidation, or discriminatory conduct
- Personal attacks, insults, or derogatory comments
- Trolling or deliberately disruptive behavior
- Unwelcome sexual attention or inappropriate content
- Publishing another person's private information without permission
- Deliberately disrupting project discussions or development
- Abusive communication in issues, pull requests, discussions, or reviews
- Other conduct that would reasonably be considered inappropriate in a professional environment

---

## 🎯 Scope

This Code of Conduct applies within all project spaces, including:

- GitHub Issues
- Pull Requests
- Code reviews
- Discussions
- Documentation contributions
- Repository-related communication
- Other official project collaboration channels

It also applies when an individual is officially representing the project in public spaces.

---

## 🛡️ Enforcement Responsibilities

Project maintainers are responsible for clarifying and enforcing standards of acceptable behavior.

Maintainers may remove, edit, or reject:

- Comments
- Commits
- Code
- Issues
- Pull Requests
- Discussions
- Other contributions

that violate this Code of Conduct.

Maintainers may also temporarily or permanently restrict participation when behavior is considered inappropriate, threatening, offensive, or harmful.

---

## 🚨 Reporting Problems

Instances of abusive, harassing, or otherwise unacceptable behavior should be reported privately to the project maintainer whenever possible.

Reports should include relevant information necessary to understand and review the incident.

All reports will be reviewed as fairly and responsibly as reasonably possible.

Maintainers should respect the privacy and security of individuals who report incidents.

For security vulnerabilities rather than community conduct concerns, refer to:

```text
SECURITY.md
```

---

## ⚖️ Enforcement Guidelines

Project maintainers may use the following guidelines when determining consequences for violations.

### 1. Correction

**Impact:** Minor inappropriate or unprofessional behavior.

**Consequence:** A private or public warning explaining the issue and requesting corrective behavior.

---

### 2. Warning

**Impact:** A violation through a single incident or repeated inappropriate behavior.

**Consequence:** A formal warning with expectations regarding future conduct. Continued violations may result in temporary restrictions.

---

### 3. Temporary Restriction

**Impact:** Serious or repeated violations of community standards.

**Consequence:** Temporary restriction from participating in project interactions, including issues, pull requests, discussions, or other communication channels.

---

### 4. Permanent Restriction

**Impact:** Sustained violations, harassment, threats, or other severe misconduct.

**Consequence:** Permanent restriction from participating in the project's community spaces.

---

## 🤝 Constructive Collaboration

When reviewing code or discussing technical decisions:

- Critique the code, not the contributor
- Explain the reasoning behind requested changes
- Provide actionable suggestions where possible
- Avoid dismissive or hostile language
- Respect alternative technical approaches
- Keep discussions relevant to the project
- Resolve disagreements through technical reasoning and evidence

Constructive code review should improve both the **software** and the **developer experience**.

---

## 🌱 Supporting Contributors

Flow Task Manager welcomes developers with different levels of experience.

Contributors are encouraged to:

- Ask relevant technical questions
- Share implementation ideas
- Request clarification during code reviews
- Suggest improvements
- Help improve documentation
- Learn from feedback
- Help other contributors when possible

Technical discussions should remain collaborative and focused on improving the project.

---

## 🔒 Privacy

Do not publish another contributor's private information without explicit permission.

This includes information such as:

- Private email addresses
- Phone numbers
- Home addresses
- Authentication credentials
- Private account information
- Other personally identifiable information not intentionally made public
